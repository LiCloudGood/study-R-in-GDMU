## 三、已知问题 / 待办

### A. 待修 Bug（优先级从高到低）

1. **`Cannot convert object to primitive value`**（日期那一讲的正则实验）
   WebR 的 `captureR` 在 R 报错时返回的 `error` 项，其 `data` 是 **RObject** 而不是字符串。
   已在 `.vitepress/theme/webr.ts` 里加了 `conditionText()` 做降级处理（RObject 有
   `async toString()`，能反解析成可读文字）——**需要真浏览器验证是否已修复**。

2. **绘图没有显示出来**（高级绘图、ggplot2 两讲）
   `webr.ts` 里已经 `evalRVoid('options(device = webr::canvas)')` 并在
   `runR()` 里把 `capture.images` 交给 `drawImages()` 画进 canvas，
   但作者反馈页面上没出现图。**需要在真浏览器里抓 console 定位**。

3. **脚本里的「错误」会中断后续代码**
   例如 `test0501.R` 的 `dts - 30`（题目本来就要求它报错）、
   `test0601.R` 的 `object 'num' not found`（删空工作区后本来就会报错）、
   `test0801.R` 的 `count_even()`（参数检查本来就会报错）。
   这些报错是**题目的考点**，但在 WebR 里一旦报错，后面的代码就不再执行。
   **建议方案**：用 R 的 `parse(text = code)` 把代码拆成一条条表达式，
   逐条 `eval` 并用 `tryCatch` 兜住错误，模拟「逐行运行」的效果。

### B. 作者提过的想法（未实施）

- **把「在线运行」换成「预先生成的静态结果」**（文字输出 + 图片直接贴在页面上）。
  作者说：「毕竟不是允许学生在线编辑的」。
  好处：绕开 WebR 的所有坑、页面更简洁、离线也能看。
  难点：本机没有 R，需要在 Node 里用 `webr` npm 包跑（约 48MB），
  且图片输出在 Node 环境下能否生成尚未验证。
- **第十周「初级绘图函数」不在网站上**：`原题/第十周原题` 有 docx 和 8 个脚本，
  但**没有答案、也没有汇总**。若补成第 14 讲，需要给 ggplot2 之后的 4 讲顺号
  （URL 会变）。
- **不做**：把「原题+答案」额外导出成 Markdown。
  理由：已有 docx / HTML / PDF 三份副本，站点讲义本身就是更适合学生读的
  Markdown，再导一份只会增加不同步的风险。
