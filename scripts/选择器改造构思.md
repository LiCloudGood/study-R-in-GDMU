# 统计方法选择器 —— 改造构思

> 选择器（`ChoiceFlow` + `public/tree-{normal,med,expert}.json`）目前**已下线**
> （见 `docs/.vitepress/config.mts` 的 `srcExclude`），原因是推荐流程不够严谨。
> 这份文档是重新设计它的思路，供作者审定；审定后再动手实现。

---

## 一、现在的问题（逐条）

把 `tree-med.json` 的问答流程完整展开后，问题集中在**六类**：

### 1. 它在问学生答不上来的问题 ⚠️ 这是最根本的问题

流程里直接问：

> 单样本检验：变量类型与分布？
> 　「连续变量，**正态分布**」→ 单样本 t 检验
> 　「连续变量，**非正态分布**」→ Wilcoxon 符号秩检验

**「你的数据是不是正态分布」这个判断，正是学生要学的东西，不是他能直接回答的前提。**
选择器把最难的一步当成输入项，等于把问题原样丢回去。学生要么瞎选，要么按自己想用的方法倒推。

**同样的问题还有「方差齐性」**：两独立样本 t 检验要求方差齐性，流程里**一个字都没提**
（`tree-med` 的 #8 节点只有「正态/非正态」两档）。而这是第 8 章的重点之一。

### 2. 该问的判据没问，不该问的问了

| 应该问（学生观察得到） | 现在问的（学生判断不了） |
| --- | --- |
| 一共多少例？（n < 40 / 40~50 / 很大） | 数据服从什么分布？ |
| 有没有明显的极端值？ | 方差齐不齐？ |
| 同一批人测了两次，还是两组不同的人？ | 配对还是独立？（没有判据提示） |
| 数据是具体数值、还是「轻/中/重」这种等级？ | 连续还是分类？（等级资料被拆散） |
| 是抽样调查，还是做了干预实验？ | —— |

### 3. 等级资料（有序分类）几乎没有路径

`tree-med` 里，三分类只分成「两个二分类 / 行×列联表 / 有序分类关联」，
**「两组等级资料怎么比较」完全没有路径** —— 而这在医学数据里极常见
（疗效「无效/好转/痊愈」、疼痛评分「轻/中/重」）。正确做法是秩和类方法，
但流程给不出来。

### 4. 有些分支在兜圈子

`#11 连续变量与分类变量分析` 的选项是：

> 「比较不同组别的连续变量」→ ✅ **t 检验/方差分析 或 非参数检验**

这是把「该用哪个」又推回给用户了 —— 它是个**选择器**，不该给出「A 或 B」。

### 5. 样本量与适用条件完全缺席

- 大样本时（n > 50）即使偏离正态，t 检验也够用（中心极限定理）—— 流程没提；
- 卡方检验「什么时候用专用公式、什么时候要校正、什么时候必须用 Fisher」——
  这是第 10 章的核心判据，流程把三者糊成一句「卡方检验/Fisher精确检验」；
- 多变量建模只看因变量类型，没提样本量、共线性、事件数（logistic 的 EPV）。

### 6. 结论只有「方法名 + 一句话」

现状输出：

> 【独立样本 t 检验】
> 比较两组独立样本的均值差异，需检验正态性和方差齐性

学生拿到这句话之后：**不会写 R 代码、不知道看哪个输出、不知道有什么坑**。

## 二、设计原则

1. **只问学生观察得到的事实**，不问需要统计判断的结论。
   凡是要判断的（正态性、方差齐性），改成**给一张判断指引 + 一个稳妥默认值**。
2. **每个分叉都要有判据提示**，不是光给两个选项名。
   例：「配对还是独立？」旁边写「同一批对象前后测两次 → 配对；两组不同的人 → 独立」。
3. **结果要能用**：方法名 + 适用条件 + R 代码 + 看哪几个数 + 常见误用 +
   **跳到对应章节的链接**。
4. **不做「A 或 B」的结论**。如果确实取决于进一步条件，就继续问下去。
5. **和 17 章知识点页联动** —— 这是现在最值得做的一步（见第四节）。

## 三、新的问答流程（草案）

核心改动：**把「分布」这一档从输入项变成「给指引 + 兜底」**。

```
第 0 步　先问设计，而不是先问分布
────────────────────────────────
❓ 你手上的数据是怎么来的？
   ├─ 一组人/一份标本，和某个已知标准比　　　　　　→ 单样本
   ├─ 同一批对象测了两次（或配对的两个部位）　　　　→ 配对
   ├─ 两组不同的人（或两种处理各一组）　　　　　　　→ 两独立组
   ├─ 三组及以上不同的人　　　　　　　　　　　　　　→ 多独立组
   ├─ 同一批人测了三次及以上　　　　　　　　　　　　→ 重复测量
   ├─ 随访到出现结局（有时间 + 是否发生）　　　　　→ 生存分析
   └─ 只是在描述这批数据　　　　　　　　　　　　　　→ 描述性

第 1 步　问变量的「测量尺度」，用大白话 + 例子
────────────────────────────────
❓ 要分析的那个指标长什么样？
   ├─ 具体数值，像身高、血压、白细胞计数　　　　　→ 定量
   ├─ 只有两类，像「男/女」「存活/死亡」　　　　　→ 二分类
   ├─ 三类以上、但彼此无序，像「A/B/O/AB」　　　　→ 无序分类
   └─ 三类以上、且有轻重顺序，像「轻/中/重」　　　→ 有序分类（等级）

第 2 步　只在这一步才「猜分布」，而且给兜底
────────────────────────────────
❓ 这批数据的样本量和外形？（不知道就选第一项，我们会给最稳的做法）
   ├─ 不确定 / 样本量偏小（每组不到 40），或图上有明显偏态、极端值
   │      → 推荐非参数方法（不依赖分布假设），并附一句
   │        「若正态性检验不拒绝且方差齐，参数法效能更高，可回看第 4 章」
   ├─ 每组 40 例以上，直方图基本对称、没有离群点
   │      → 参数方法（t / 方差分析），并提示「先跑一下正态性与方差齐性」
   └─ 每组 40 例以上但有明显偏态
          → 推荐参数方法 + 说明「大样本下中心极限定理保证近似可用」，
            同时给出非参数作为备选

第 3 步　（仅两独立组 / 多组）方差齐性
────────────────────────────────
❓ 各组数据的离散程度看起来差不多吗？
   ├─ 差不多 / 不确定　→ 用默认更稳的写法（Welch t 检验 / Welch ANOVA）
   ├─ 差很多　　　　　　→ Welch 或变量变换，指向第 8 章
   └─ 已经做过方差齐性检验 → 按结果走，并给出判据
```

**每个结论的输出结构**（这是和现在差别最大的地方）：

```markdown
## 推荐：Welch 两独立样本 t 检验
（为什么是它，一句话）

### 适用条件
- 两组独立
- 近似正态 **或** 每组 n ≥ 40
- **不要求方差齐**（这正是选 Welch 而不是合并方差 t 的理由）

### 在 R 里怎么做
```r
t.test(value ~ group, data = d)          # R 默认就是 Welch
# 若要合并方差写法：t.test(value ~ group, data = d, var.equal = TRUE)
```

### 输出看这几个数
- `t` 与 `df`：Welch 的自由度通常不是整数，属正常
- `p-value`：与检验水准 α 比
- `conf.int`：两组均数之差的 95% 可信区间

### 容易踩的坑
- 配对设计误做成组检验（最常见，会让 p 值偏大）
- 只报 p 值不报效应量与可信区间

### 想弄懂原理 → 第 8 章 t 检验  ← 链到知识点页
```

## 四、和 17 章知识点页联动（重点）

**这是新选择器最值得做的一件事**：现在 17 章知识点页已经写好了，选择器的每个结论
都可以直接跳过去 —— 学生从「我该用什么」一步到「这个方法的原理、条件、R 实现、坑」
全都在同一个站内，不需要再搜。

对应关系（每章都有现成的 slug）：

| 选择器的结论 | 跳转 |
| --- | --- |
| 描述性统计（定量 / 定性） | `/Health-statistics/04-describing-quantitative-data`、`/05-...` |
| 单样本 t、配对 t、两独立 t | `/Health-statistics/08-t-test` |
| 方差分析、两两比较 | `/Health-statistics/09-anova` |
| 卡方、Fisher、McNemar | `/Health-statistics/10-chi-square` |
| 秩和、符号秩、Kruskal-Wallis | `/Health-statistics/11-nonparametric` |
| 相关、OR/RR | `/Health-statistics/12-bivariate-association` |
| 直线回归 / 多元回归 | `/Health-statistics/13-linear-regression` |

## 五、实现步骤（审定后）

1. **重写题库结构**：从「一题目多选项」扩成
   `{ 问题, 选项（带判据提示）, 下一步, 结论（含条件/R 代码/坑/章节链接）}`
2. **三个版本怎么处理**：现在的「普通版 / 医学生版 / 专家版」是按**知识深度**分的，
   但**统计方法的选择依据和研究对象无关** —— 建议改成按**场景**分：
   「实验/临床试验」「观察性研究/调查」「诊断试验」「生存随访」，或者干脆合成一套，
   用「展开看更多」控制详细程度。
3. **给每个结论补 R 代码**：可以直接从 17 章里抽（那些代码都已实机跑过）。
4. **写校验脚本**：检查每个结论都链到了真实存在的章节页、没有死链、
   没有「A 或 B」式的结论。
5. **恢复上线**：去掉 `config.mts` 里的 `srcExclude`，把侧栏条目加回去。

## 六、要请作者定的几件事

1. **三个版本（普通/医学生/专家）保留还是一套？**
   我倾向合成一套 + 可展开的详细程度，因为选择依据和身份无关；
   但如果三个版本是给不同课堂用的，那就保留。
2. **结论的详细到什么程度？** 是「方法名 + 一句话 + 章节链接」，
   还是「连 R 代码和输出解读都给」？后者更实用，但页面上会很长。
3. **愿不愿意接受「推荐非参数作为兜底」这个取向？**
   现在的流程倾向于"先判分布再选"；我建议改成"分不清就推荐更稳的那条路"，
   对初学者更安全，但可能让部分学生少学一个判断步骤。
